## What it is

False Alarm: a party game for 3+ people in one room. Each player is shown a phrase to shout and a set of buttons
for other players' phrases; when you hear one, you tap it. The timer shortens as the score rises
(`Game.getMaxTime`, mirrored in the client), and a wrong tap costs double. Last commit 2025-09; built with Replit's agent.

- **Client** (`src/client`): Create React App (react-scripts 5, React 18), a class `App`, a custom service worker,
  a QR code for joining. `api.js` opens a same-origin `socket.io-client` 2.x connection; the page reloads 2 s after any
  disconnect.
- **Server** (`src/server`, about 400 lines): Express serves `build/` and socket.io 2.0.4 handles `createGame`,
  `subscribeToGame`, `ready`, `clickPhrase`. All state (`GameManager`, `PlayerManager`, `Game`, `Player`) is in memory.
  Game ids are 4 random letters; a client keeps its player id in `sessionStorage` to reconnect.
- **Runtime needs:** Node and one port (`PORT`, default 5000, binds 0.0.0.0), websockets (polling fallback), no
  database, no env vars, no secrets. Replit config: `.replit` (cloudrun deployment: build `npm run build`, run `npm start`),
  `replit.nix` (nodejs-16), and the dev setup that needs port 5000 for the webview with a CRA proxy to 3001
  (`ARCHITECTURE.md`, `replit.md`). `npm install` runs `postinstall: npm run build`.

## Review

Correctness (read from the code; the first was reproduced)
- **One bad message kills the server.** `ready` with an unknown game id (`gameManager.getById` returns undefined,
  then `game.generateRound()`) throws and, with no handler, exits the process (reproduced). Likewise `clickPhrase`
  with an unknown game or player, or from a player with no phrases left (`player.phrases[0].Phrase`), and `getById(gameid)`
  when `gameid` is missing. On Replit this was a restart; on a shared server it is a remote kill switch.
- Games and players are never deleted (`gameManager.games`, both `PlayerManager` maps), so memory grows for the life
  of the process. `Game.timeout` starts undefined, harmless but untidy.
- Anyone can `ready` any game by guessing its 4-letter id (about 457 k values) and anyone can reuse a player id.
  Fine for a party game; not for anything with stakes.
- Two console.log calls per event; noisy but not harmful.

Security
- No secrets in the tree or in 134 commits of history (no `.env`, keys or tokens; `.replit` has only paths and workflows).
  Old test-result screenshots and videos were committed once and then deleted (repo is still only 1.2 MB).
- No auth, no rate limits, no input validation on socket events (see above).
- `npm audit`: 82 vulnerabilities (6 critical, 46 high). Nearly all are react-scripts 5 build tooling (webpack-dev-server,
  loader-utils, nth-check and so on), which ships nothing to production. The runtime-relevant ones are
  **socket.io / socket.io-client 2.0.4** (old engine.io, ws, and the optional `uws@0.14.5` that tries to compile with node-gyp)
  and express 4.21 (4.22.3 is current). Several open Dependabot branches on the remote are stale.
- Unpinned test dependencies (`@playwright/test`, testing-library, `wait-on`) sit under `dependencies`, so a production
  install pulls them in.

Outdated (npm outdated): socket.io 2.0.4 to 4.8.4 (breaking, client and server together), react 18 to 19, express 4 to 5,
Playwright 1.55 to 1.65. react-scripts 5 is unmaintained; moving to Vite is the natural fix for the build tooling.

## Rehosting plan (Sterling's setup)

Smallest path, one hostname: build the CRA bundle and run `npm start` on realtime-1 as a systemd service, with deploy-kit's
Caddy site for `false-alarm.rt.sterlinghirsh.com` (reverse proxy including websockets). The server already serves `build/`, so
the same origin serves client and sockets, as asteroid-blaster does. It needs no database and about 50 MB.

Split path, matching the convention in `DEPLOYMENTS.md`: static client on Cloudflare Pages at
`false-alarm.sterlinghirsh.com`, server only at `false-alarm.rt.sterlinghirsh.com`. That needs the socket URL as a build-time
setting (`REACT_APP_SOCKET_URL`, which `ARCHITECTURE.md` already sketches), CORS on the server, and the service worker
re-checked for the new origin. Do this only after deploy-kit's host layer and the Cloudflare account exist.

Order of work: (1) add an error guard around every socket handler and validate ids (the crash above); (2) move test-only
packages to devDependencies, fix the Playwright config; (3) upgrade socket.io to 4 on both sides (the event API is
unchanged; set `transports` and CORS); (4) game cleanup on idle; (5) deploy as above; (6) stop paying for Replit once the
new hostname is live (Sterling's step).

## Rework under kitten: optional, probably not

The server is a four-class room of a few hundred lines, with no simulation or rendering that would use kitten's SoA/SIMD
core; the value would be the shared deploy path and a typed Rust room server. Better to harden this Node server and
rehost it (an afternoon). Revisit only if Sterling wants every realtime app on one stack, or a Quest/WebXR version. If so,
the phrases and scoring (`phrases.json`, `getMaxTime`) are the only logic to port.
